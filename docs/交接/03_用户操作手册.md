# 庞巴迪影视工作台：用户操作手册

整理日期：2026-10-25。日常操作按“新建项目 → 自动协作 → 人物资产 → 分镜 → 创作画布 → 成果汇总”进行。

## 1. 打开哪个版本

| 想做什么 | 打开方式 |
| --- | --- |
| 继续原来的真实项目 | 双击桌面“庞巴迪影视工作台.app”打开本机入口，或打开 `http://127.0.0.1:8767/` |
| 使用云端试用 | Mac 菜单“显示 → 打开在线试用（浏览器）”，或打开 [云端 BYOK 试用](https://pangbadi-film-workbench.zainabadenike433.chatgpt.site)；登录后配置自己的 API Key |
| 网页无法访问时启动原后台 | 在原项目目录双击 `启动工作台.command`，再打开 8767 |
| 试运行桌面交付的源码副本 | 在 `01_源码与资源` 中双击 `scripts/start-portable.command`，按终端输出打开默认 `http://127.0.0.1:8768/` |
| 查说明、源码和备份位置 | 桌面交付 HTML 导航 |

交付副本使用独立 `data/portable-runtime/` 和 `prompts` 岗位快照；原 8767 继续使用原数据。不要把双击 `index.html` 或聊天内嵌预览当作可执行后台。内嵌预览本次超过 1 MB 限制未构建成功，本机网页可独立使用。

本机文字执行需要本机可用且已登录的 Codex CLI，媒体生成需要 RunningHub 凭据和网络。云端试用不依赖访问者本机的 Python 或 Codex：登录后点击顶部“模型连接”选择 DeepSeek、通义千问或 OpenAI，填写该服务的个人 Key；需要图片／视频时再配置自己的 RunningHub Key。交付源码与云端页面均不附带可供他人消费的真实账号密钥。

云端已部署上线，当前完成模拟接口及隔离检查；尚未进行真实付费文字、图片、视频生成和浏览器端到端验收。请将其作为 BYOK 试用入口使用。

## 2. 页面怎么分工

| 位置 | 用来做什么 |
| --- | --- |
| 总策划台 | 看示范案例、真实成果、当前项目和待处理；示范有标签，与真实作品分开 |
| 项目协作 | 当前项目、自动协作、人物、分镜、画布、素材、任务、版本和成果汇总 |
| 任务看板 | 管理责任人、复核人、依赖与拍板；登记或执行明确任务 |
| 团队伙伴 | 查看 21 位伙伴及岗位，打开个人工位 |
| 共享成果 | 查看已有文稿和素材入口，按来源与项目理解内容 |
| 工具与连接 | 检查文字执行器、配置 RunningHub、测试连接、打开外部平台 |
| 回收站 | 恢复、单条彻底删除、批量删除、清空 |
| 数据备份 | 导出／恢复项目 JSON；不是完整运行库备份 |

首页大灯塔和两张方案图来自设计参考的图片区，周围文字、伙伴与按钮是实际页面。真实成果目前默认最近 4 份小卡；用户后来要求的“两倍大封面和自动海报”仍未完成。

## 3. 创建项目并选审核方式

1. 点击“新建项目”。
2. 填写项目名、简报、类型，选择制作与复核伙伴。首次影视制作建议用“影视短片”。
3. 选择“团队连续完成”或“逐步审核”。连续模式只在最终文稿统一审阅；逐步模式在剧本、美术设定、最终交付停下。
4. 创建后进入“自动协作”。项目说明已自动带入，协作方式可直接选择；需要修改说明时展开“查看或调整项目说明”。
5. 点击“按现有说明开始”。页面进入执行阶段后，不需要再填一遍新建需求表。

创建模板只是建立任务与决策，不会自行调用模型。游戏项目可用游戏工位、团队对话和任务模板，当前固定六阶段自动制作不支持游戏工程生成。

## 4. 阅读、审核与返修文稿

自动协作按 R11 制作规划、R03 剧本、R05 美术、R04 分镜、R06 提示词、R11 汇总推进。点击交付查看全文，也可下载 Markdown。

- 满意：在审阅点点击“认可这版，继续”。美术稿批准后可进入人物资产；最终文稿按钮会引导人物准备。
- 要改：写具体意见并“交回修改”。描述保留什么、改什么、期望输出；旧稿保留在历史版本。
- 修改已完成阶段：展开该阶段的“修改这个阶段”。上游改动会使相关下游重新制作。
- 想暂停：点击“暂停协作”；稍后“继续协作”。失败时排除错误后“从本步继续”。
- 已结束，想做新一轮：展开“发起新一轮协作”，检查说明与模式后开始。
- 出现“版本已更新”：先看最新稿，再确认使用当前版本，不直接提交旧审阅意见。

当前文字执行器不会自己浏览网页、读取屏幕、做真实素材质检或发布。要它依据资料工作时，把必要正文放到项目说明或对话里；待核实信息明确标出。

云端点击“开始”先保存为排队状态，保持页面打开并轮询后才继续执行；每次请求最多推进一个角色或阶段，模型回复较慢时请求可能持续数分钟。不要把关闭网页理解为已启动无限期后台执行。暂停不能保证取消已经发给服务商的请求，已发出的调用仍可能计费。出现“结果未知”时系统不自动重试：先核对供应商记录，再明确选择重新执行，避免重复调用。

## 5. 制作人物资产

逐步审核中，确认 R05 美术稿即可进入人物资产，后台文字分镜可以继续。连续模式则在最终总审后准备人物。

人物表左侧是姓名和介绍，中间是定妆候选／已采用图，右侧是操作。员工头像不作作品角色参考。

1. 先核对角色是否齐全、介绍是否准确。缺角色可“＋ 新建人物”，分别填名字、介绍和定妆提示词。
2. “提示词编辑”修改定妆要求；“美术优化”打开大窗口，左侧看图，右侧改提示词和填写优化要求。
3. “放大编辑 ↗”扩大窗口，“还原窗口 ↙”恢复，“完成编辑”、关闭或 Escape 退出。查看保存状态后再离开。
4. R05 返回建议后可先编辑，点击应用才更新提示词。仅查看建议不会生图；过时建议不会直接覆盖后来修改的草稿。
5. 点击“画质 / 风格”选参数，勾选需要生成的角色，再单张生成或批量生成。
6. 查看本批费用后确认。图片返回时检查，再点“采用这张定妆”；一组都满意可“整组采用定妆”。
7. 人物准备好后点击“进入分镜”。纯场景无需虚构人物。

提示“设定已改 · 需更新”时，重新生成并采用当前版本。没有已采用定妆的含人物镜头会被阻止生成；采用新图后旧镜头结果仍保留，需核查是否需要重做。

## 6. 在画布生成图片与视频

### 自动带入的内容

已确认文稿会带入镜号、图片提示词、视频提示词、来源和默认模型。每镜对应图片与视频两类节点；镜头图片完成后，图生视频自动使用本镜当前成功图片作首帧。分层镜号如 `S01-001` 会完整保留。

默认图片用 Seedream 5 Pro；含人物镜头自动使用已采用人物参考。自动镜头视频默认 Seedance 2.5 图生视频。自由新增视频需按用途选择模型和必需输入，不一定能直接复用镜头自动配置。

### 操作步骤

1. 核对分镜，点击创作画布；人物未完成时先回人物资产处理。
2. 点击卡片的“画质 / 风格 / 提示词”，检查或修改该镜内容。
3. 先勾选需要的图片，点击单卡生成或“生成所选”，检查预计费用与明细并确认本批。
4. 等图片成功，检查结果后再选择对应视频生成。没有首帧时不能凭空开始图生视频。
5. 不满意就改该节点提示词／参数，重新报价生成；旧结果在项目素材中保留。

不必逐镜重新选择一次默认模型，也不必每张图先填一套接口表单。每批费用仍需确认一次；人物采用和文稿审阅是另外的创作决定。

### 画布移动和布局

- 拖动空白处平移，拖动卡片顶部调整位置。
- 用缩放按钮，或 Control／Command 配合滚轮缩放；“全览”查看整体。
- 顶部镜头导航定位某镜；图片在上、视频在下。
- “＋图片”“＋视频”新增自由创作节点。
- 可收起右侧编辑器，切换“团队对话”和“提示词”。专注模式铺满工作区，退出专注或 Escape 返回。
- 可拖动布局分隔线调整支持的页面栏宽；项目右侧协作可“收起协作”／“展开协作”，窗口偏好单独保存。

自动同步期间若正在输入、切页或打开弹窗，工作台会保留当前操作；之后主动进入对应页即可，不需要重新建项目。

## 7. 参数、风格、提示词怎么改

| 控件 | 操作与限制 |
| --- | --- |
| 画面比例 | 图片常用 9:16、16:9、1:1、3:4 等，范围由当前模型决定；非标准值显示自定义 |
| 清晰度 | Seedream 常用 1K／2K；改清晰度保留当前比例，像素值可在高级设置查看 |
| 视频参数 | 以模型实际能力显示分辨率、生成时长、声音、草稿等；区分原生和超分 |
| 内置风格 | 31 种风格，也可保持原稿；通过实际提交提示词查看叠加内容 |
| 批量画质 | 只对兼容的同模型、同类所选节点应用，保留目标自身比例；不覆盖提示词和参考 |
| 批量风格 | 与画质分别应用，不顺带改变尺寸 |
| 更换模型 | 展开高级设置；参数随接口改变，必需参考图需重新满足 |
| 优化提示词 | 人物交给 R05，镜头交给 R06；用户应用建议后才改变草稿 |

“分镜目标时长”与“模型生成时长”不同；目标 2 秒、素材 5 秒时，后续剪辑取用，不会在工作台自动裁成 2 秒。

改模型、提示词、参数、所选节点或预算后重新报价。浏览、平移、缩放和移动卡片不主动使报价失效，但官方报价自然过期后仍需刷新。降低画质或缩短时长是否便宜，以重新取得的实际报价为准。

## 8. RunningHub 怎么配置

进入“工具与连接”。日常只需把模型 Key 保存并测试一次，之后回项目选模型生成即可。本机下方工作流连接是可选项，不需要两种方式都配置；云端试用暂不提供工作流节点模式，使用模型 API 通道。

### 云端个人配置

| 配置 | 对应字段 | 填写内容 |
| --- | --- | --- |
| 文字服务 | `textProvider` | DeepSeek、通义千问或 OpenAI |
| 文字模型 | `textModel` | 所选服务支持的具体模型 |
| 文字 API Key | `textApiKey` | 该文字服务的个人 Key |
| RunningHub 个人 Key | `runninghubApiKey` | 独立的个人连接凭据；保存不代表云端已支持工作流节点 |
| RunningHub 模型 Key | `runninghubModelApiKey` | 模型 API 要求的 Key；图片／视频模型通道使用此项 |

只在自己的配置窗口填写；不要将 Key 发到聊天、公开文档或源码仓库。先保存并检查连接状态，再回项目开始制作；未配置的服务不能因为页面存在按钮就直接调用。

### 模型 API 连接

1. 在 RunningHub 个人账号获取符合模型 API 要求的“企业级-共享”类型 Key；该类型名称不等于需要企业账户。
2. 在“模型 API 密钥”密码框填写，点“保存模型连接”，再“测试模型连接”。已保存时留空表示保留，移除需勾选相应选项。
3. 回项目选择模型和参数，读取官方报价。测试连接不生成；保存成功也不等于所有模型都能使用。

### 本机个人工作流 API

1. 展开“可选 · 个人工作流 API 连接”，填消费级个人 Key、默认工作流链接／ID和参考单价、币种。
2. 保存并“测试账户连接”。
3. 读取工作流参数，明确把提示词映射到实际接收它的字段，再在项目中生成。

无限画布链接不是工作流 ID。AI 应用与工作流也不能随意互换；当前通用工作流接口按 ComfyUI 字段契约处理。素材输入依实际接口要求，常见是公开 HTTPS 链接；没有通用本地文件上传或任意 Base64 通道。

模型通道调用官方 price-preview；工作流参考价来自配置，两者都不是服务商扣费硬上限。预算可选，仅在提交前核对。任务结果不明时先到平台核对任务编号，不要反复新建生成请求。

“打开无限画布”只跳转 RunningHub 网页，外部画布任务目前不自动回填本地。国际站 Image 2 尚未接入。下架接口显示禁用时，请选当前可用模型，不要把旧失败任务当新模型已经失败。

本机 Key 保存在本机服务端配置；云端 Key 按登录账户绑定并加密保存，公开接口响应不返回密钥明文，也不会自动带入原本机的 Key。不发到聊天、不贴截图、不提交 GitHub。连接权限、价格和模型是否可用可能变化，应以当前测试与平台结果为准。

## 9. 去哪里看进度和结果

- 画布：本节点的真实排队、执行、成功、失败或未知状态；活跃批次会查询进展，不显示编造的生成百分比。
- 项目“任务”：查看执行编号、状态与错误；需要时查询服务商最新状态。
- 项目“素材”：成功返回的图片、视频及文本结果；可预览和查看原文件。
- 项目末尾“成果汇总”：顶部主展示，之后生成结果、文稿、默认收起的完成任务。

在生成结果中“设为主展示”选择一张图或视频；视频可“设为最终成片”，显示“你已指定”。这个标签不表示自动剪辑完成、专业质检通过或已发布。远程播放器可用也不代表重要文件已保存到电脑。

## 10. 与伙伴单独沟通和手动任务

“团队伙伴”中打开工位，选择对话或产出。项目内可 `@姓名` 或 `@R03` 指定伙伴，或选择最多 4 人依次协作；后者读取前序保存交付。独立工位不自动带入当前项目。需要围绕项目工作时优先在项目内发起。

本地便笺只记录内容，不调用模型。手动任务看板要求责任人与不同复核人，依赖及拍板未满足会阻塞；模型返回文字不会自动把任务改为完成。自动协作阶段完成、手动任务完成、专业复核和总策划认可分别记录。

## 11. 删除与恢复

普通卡片垃圾桶、画布“删除所选”会将内容移入回收站。项目删除会说明范围，恢复项目不会自动恢复之前单独删除的内容。删除节点不会同时删除它生成的所有媒体。

回收站中：

- “恢复”找回对应内容。
- 单条“彻底删除”、勾选后“删除所选”、或“清空回收站”，都会先弹出不可逆确认列表；取消不删除。
- 最后确认仅处理这次确认范围。仍被引用、正在执行、排队、结果未知或同步未完成时先解决阻塞。
- 永久清理不能从回收站恢复，但不会清除 RunningHub 云端文件、外部导出或独立备份，也不会取消云端任务。

## 12. 保存、备份与迁移

原项目后台数据在 `data/runtime/`，交付副本为 `data/portable-runtime/`。正式运行库、运行文件与连接配置需要一起备份；项目 JSON 主要包含项目、任务和人工记录，不含全部运行正文、岗位快照或远程媒体原文件。

云端账户数据与本机 8767、便携 8768 都独立，不自动迁移或同步。切换 Mac 的本机／云端入口只是切换访问地址，不会上传原数据库、原媒体或原 Key。云端账号的配置和项目由该账号独立保存；不要把云端登录成功当作本机项目已备份。

多个窗口并发编辑出现冲突时，先导出本页副本，再决定使用哪版；不要忽略提示反复覆盖。网页和 Mac 客户端连接相同后台时共享正式数据，窗口布局和未提交草稿可能分别保存。

桌面 `02_本地私有数据备份` 不进 GitHub；`01_源码与资源` 可用于开发与版本管理。恢复私有备份前先备份目标、停止目标服务并确认数据目录，不把它直接混进正在运行的交付副本。重要媒体要另行下载保存，备份数据库只保留链接不等于备份远程文件。

Mac 0.6 已安装并支持本机／云端双入口。本机入口依赖原项目目录、Python 和 Codex 登录；关闭窗口或退出应用后，本机后台通常继续，电脑休眠、关机或服务退出仍会影响调用。云端文字推进需要页面继续轮询。当前未验证自包含的商业分发包、正式公证或其他电脑的安装兼容性。

## 13. 常见问题

| 现象 | 处理 |
| --- | --- |
| 本机网页访问不了 | 确认打开的是原 8767 还是副本 8768；启动对应脚本，不并行抢同一端口 |
| 云端访问或调用失败 | 检查网络与登录状态，再在工具与连接核对自己配置的服务、模型、Key 和额度 |
| 文字执行器未就绪 | 本机检查 CLI 登录；云端检查个人文字服务配置。保存说明后再开始 |
| 云端一直排队 | 保持页面打开并允许轮询推进；检查文字连接状态，不连续重建同一任务 |
