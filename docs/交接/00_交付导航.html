影视制作 SOP

适用：庞巴迪影视工作台本机版，短片、宣传片、漫剧和动画的文稿、人物与镜头素材制作。用户是总策划。标准顺序：

明确需求 → 自动协作文稿 → 人物定妆 → 核对分镜 → 镜头图片 → 镜头视频 → 外部剪辑／检查 → 成果与交付。

当前自动协作负责文字流程，画布负责生成素材；外部剪辑与最终专业验收仍需要另外完成。

1. 建立项目与制作基准

总策划填写项目名称和简报，选择“影视短片”或用于影视工作的“影视 × 游戏联动”，并保留至少一位制作与一位复核伙伴。创建项目只建立资料和待办，点击自动协作的开始按钮才调用文字模型。

简报建议一次写齐：

项目：
目标与受众：
作品类型、时长、画幅：
故事主题与希望观众感受到什么：
原始文稿／小说段落／必须保留内容：
人物及关系：
视觉风格与参考：
对白、旁白、配乐要求：
禁止改动、待核实信息、版权或平台限制：
本轮交付：完整剧本、人物设定、逐镜稿和生成提示词。

只有链接而没有正文时，先自行整理可用文字资料。当前员工文字执行器不会自动联网阅读全文或核查版权；资料中的事实、创作建议和待核实项需要分开标识。

完成条件：总策划能确认作品范围、素材依据及不允许改变的内容，而不只是一个模糊主题。

2. 选择文稿审核方式

方式 团队如何推进 总策划何时操作 适用情况
团队连续完成 六阶段连续交接文字成果 最终文稿统一审核，也可对已完成阶段定点返修 简报充分、希望少打断的项目
逐步审核 剧本、美术设定、最终交付停靠 每个停靠点查看全文后认可或交回修改 新题材、人物要求高、首次制作

新建项目的选择会带入自动协作，开始前仍可调整。两种方式最终都需要总策划确认；“连续完成”不代表自动扣费生图或取消人物采用步骤。运行期间不应把修改项目默认选项当成已改变当前这轮审核方式。

3. 六阶段文字协作

顺序 岗位 正式输出 本步检查重点
1 陆观行 R11，影视统筹 制作简报、范围与约束 时长、受众、必保留点、待定事项清楚
2 林砚舟 R03，编剧 完整故事、对白／旁白、动作正文 有可阅读正文；人物目标、情节、结尾一致
3 周予白 R05，美术指导 人物、场景、道具和视觉基准 每个人物单独编号；介绍、外貌、服装、定妆提示词分开
4 沈知遥 R04，导演／分镜 稳定镜号、时长、景别、动作、运镜、声画设计 一镜一意图、镜号不混、时长合计与故事一致
5 姜云岫 R06，AI 影像 每镜图片提示词、视频动作提示词与参考要求 提示词归属准确；人物／场景引用、首帧意图完整
6 陆观行 R11，影视统筹 文稿清单、冲突检查与制作交接 版本统一，缺失项明确，不把文字自检称为媒体已完成

在“自动协作”查看当前阶段、负责人、真实执行记录及成果全文。认可前先读稿件；不满意时在该阶段填写具体修改要求，保留应该不变的内容，再“交回修改”。上游返修会让受影响下游按新版重做，旧稿保留。

需要停下时使用“暂停协作”；失败排除后用“从本步继续”。等待模型期间对话不会自动变成正式返修指令，正式修改应通过阶段审阅入口提交。

完成条件：最新文稿经总策划确认，人物、场景、镜号和生成提示词相互对应。R11 的检查是模型自检，不等于独立专业审核。

4. 人物定妆先行

逐步模式下，R05 美术设定获总策划批准后即可进入人物资产；连续模式需等最终文稿总审。人物资产页在分镜前，员工头像与作品角色是两类资料。

  1. 检查提取出的人物名称、介绍、身份和版本。占位稿应明确是占位，不作为原作已核实设定。
  2. 通过“提示词编辑”调整外貌、发型、服装、视图与不可改变项；通过“美术优化”让 R05 给建议，查看并应用后才更新提示词。
  3. 选取需要生成的人物，设置比例、画质与风格。先小批检查方向，再扩大制作量。
  4. 获取本批报价，检查数量与费用后确认一次。图片返回后查看脸型、发型、服装、视图和彼此辨识度。
  5. 满意时“采用这张定妆”，或检查一组候选后“整组采用定妆”。生成成功不会自动等于人物已采用。
  6. 需要的人物均准备好后进入分镜。

完成条件：本镜要引用的人物都有当前有效定妆。纯场景项目明确无需人物，可直接继续。后台文字分镜可以在美术批准后继续编写，当前没有“人物图确认后才允许写文字分镜”的硬闸；含人物镜头图生成则受定妆引用约束。

改变人物设定会让原确认失效；新定妆采用后，要重新检查受影响镜头。旧图、旧视频保留，但不能把缺少当前人物版本证据的旧图直接当新镜头首帧。

5. 核对分镜并进入画布

  1. 在“分镜”核对镜头数量、完整镜号、人物关联、构图、时长与来源版本。
  2. 已确认文稿会准备对应图片和视频节点。S01-001、S01-002 等分层镜号分别保留；不是每个场景都重新手建一个空表单。
  3. 人物齐备后进入“创作画布”；每镜图片在上、视频在下，提示词、默认模型与参数已带入。
  4. 如当前在编辑、切页或开着弹窗，后台同步不会强制抢走页面。之后从人物资产、分镜或画布入口继续即可。

出现漏镜或空提示词时，先查 R04／R06 原文及版本，返修不符合结构的源稿，再同步；不要用无来源的节点补成“已交付”。

6. 先图后视频，按批确认

制作步骤 默认衔接 总策划要检查什么
镜头图片 含人物镜头自动引用已采用定妆；纯场景使用文生图 人物一致性、场景、构图、遮挡、画幅
镜头视频 自动引用本镜当前成功图片作首帧 动作、运镜、时长、稳定性、声音和可用剪辑区间
返修 修改该节点提示词／参数后重新报价生成 保留项与改动明确，旧结果不要误认为新版本

点击一个节点的生成按钮，或勾选多个节点后“生成所选”，先取得批次费用，再确认提交。不要期待尚未生成的首帧自动满足图生视频必需输入；先得到可用镜头图，再做视频。

图片常用参数为画面比例和清晰度，像素及其他字段在高级设置。视频按当前模型显示分辨率、生成时长、声音等；原生与超分档位分开。31 种内置风格可选，也可保持原稿。提示词优化建议必须由用户应用才替换当前草稿。

“应用画质到所选”只覆盖同模型、同类的兼容节点，保留目标比例，不覆盖提示词与参考；风格批量应用是单独操作。修改模型、参数、提示词或所选节点后旧报价失效，重新取价；单纯平移、缩放、切镜或拖动位置不主动使报价失效。

预算只是提交前核对，实际扣费以 RunningHub 账单为准。停止批次仅停止尚未提交部分；已提交或结果未知时先查询平台，不重复点击新建任务。

7. 素材质检与外部合成

图片和视频返回到本镜、项目素材和任务记录。依次完成以下检查，再决定是否采用：

  • 图片：打开实际文件确认清晰度、人物一致性、手脸细节、文字、水印、构图及可用范围。
  • 视频：从头到尾播放，核对动作衔接、人物变化、画面闪烁、声音与黑帧；不能仅凭缩略图或加载成功判断质量。
  • 时长：分镜目标时长与模型素材时长分开。例如目标 2 秒而模型生成 5 秒，需要后续剪辑取用，不代表已自动剪好。
  • 版本：新旧提示词和定妆版本分清，避免把旧结果用于新文稿。

当前工作台不自动完成剪辑、配乐、字幕、混音、母版导出。将合格素材交给外部剪辑工具处理，记录版本和成片文件；完成全片播放、技术检查、素材权利与发布平台核对后再交付。

8. 交付、归档与清理

项目末尾“成果汇总”提供主展示位。可将一张图或一段视频“设为主展示”；只有确认要代表该项目的视频才“设为最终成片”。这是展示选择，不会自动补齐播放、专业验收或发布证据。

交付时至少保留：最新剧本、人物基准、逐镜表、实际生成提示词、采用素材、版本关系、最终文件与检查记录。远程链接可能失效，重要成片与素材应另行保存；项目 JSON 不包含所有后端运行文件和远程媒体。

不用的内容先移入回收站。清空／彻底删除必须核对确认列表；仍有引用、在途任务或同步未完成时先解决阻塞。清理本地内容不会删除 RunningHub 云文件或独立备份。

本 SOP 的闭环完成标准：文本已确认、人物与镜头素材已检查、全片已实际合成播放、专业问题已处理、总策划认可最终版本。当前软件不会因为六阶段文字完成而自动宣称这些条件全部满足。

整理日期：2026-10-29。本文介绍当前本机版。操作顺序为“新建项目 → 自动协作文稿 → 人物资产 → 分镜 → 创作画布 → 成果汇总”。分镜文稿可以先产生，含人物的镜头图制作需要先采用人物定妆。

1. 启动与版本

用途 打开方式
继续本机真实项目 原项目目录双击 启动工作台.command，或使用既有 Mac 客户端；网页为 http://127.0.0.1:8767/
试用 GitHub／交付副本 项目目录执行 bash scripts/start-portable.command；默认 http://127.0.0.1:8768/
阅读交接资料 docs/交接/ 中的 HTML 导航和 Markdown 手册

便携副本使用独立 data/portable-runtime/ 和包内 prompts/。原 8767 使用原运行数据；不要覆盖原数据库。双击 index.html 只打开静态文件，不能代替 Python 后台。

文字任务需要本机已登录 Codex CLI，图片／视频需要自己的 RunningHub 连接。仓库不附真实密钥。online/ 是单独云端版本，不能用本手册推断它已同步最新本机功能；本次源码推送不重新部署线上，也没有验证旧线上入口当前可用。

首页作品仍以最近 4 份卡片排列。两倍大封面与自动挑选视频精彩帧尚未完成，不能将历史设计图当作已经上线的行为。

3. 新建项目与审核模式

  1. 点击“新建项目”，填写项目名、简报、项目类型和伙伴。
  2. 选择“团队连续完成”或“逐步审核”。前者连续完成文稿后总审；后者在剧本、美术设定、最终文稿节点等待审核。
  3. 创建后进入“自动协作”，说明已经带入。需要调整时展开项目说明，不用重填需求表。
  4. 点击“按现有说明开始”。创建项目本身不会调用模型。

影视自动流程：R11 制作规划 → R03 剧本 → R05 美术设定 → R04 分镜 → R06 提示词 → R11 汇总。游戏伙伴可做工位与项目文字协作，当前固定流程不自动制作可运行游戏。

4. 审核与返修文稿

  • “认可这版，继续”：确认当前版本。美术稿批准后可准备人物资产。
  • “交回修改”：写明保留什么、修改什么；旧稿会保留。
  • “修改这个阶段”：返修已完成阶段，上游变更会影响下游。
  • “暂停协作”／“继续协作”：控制后续执行；失败后排除原因再从本步继续。
  • “发起新一轮协作”：已有一轮结束后开启下一轮，不要靠重复新建项目解决文稿问题。

出现版本冲突先读取最新稿。当前文字执行器不会自行浏览网页、检查真实画质或发布；必要资料正文应放入项目说明或对话，未经核实的信息注明待核实。

5. 人物资产与参考图窗口

逐步模式确认美术稿后进入人物资产，连续模式在总审后准备人物。表中姓名介绍与定妆提示词分开，员工头像不会充当作品人物。

  1. 核对人物是否齐全，缺少时“＋ 新建人物”，填写名字、介绍与定妆提示词。
  2. 点击“提示词编辑”修改描述；“美术优化”可向 R05 提要求，确认应用后才更新提示词。
  3. 点击人物行的“参考图”，选择文件或拖入图片。
  4. 为每张图选择“整体参考、人物外观、服装造型、构图动作、画风色调”，并填写希望保留／改变的部分，例如“参考发型和外套剪裁，背景重新设计”。
  5. 可点缩略图查看大图，也可移除引用；“放大编辑 ↗”扩大窗口，“还原窗口 ↙”恢复。看到保存完成后再离开。
  6. 用“画质／风格”调整生成参数，选择人物后单张或批量生成；查看本批报价后确认。
  7. 图片返回后检查，满意再“采用这张定妆”，或“整组采用定妆”，随后进入分镜。

参考图支持 PNG／JPG／WebP，每张不超过 10 MB，每节点最多 10 张。每图说明最多 1,000 字；模型可能对“已采用人物图 + 上传参考图”的总张数有更小限制，页面会校验。重复选择同一图会保留用途和说明，不重复添加。

图片先存本机，生成准备时才上传 RunningHub。有参考时自动选可用的同系列图生图接口，并保留兼容的尺寸和清晰度；没有兼容接口会提示调整模型。参考图与文字可以指导结果，但不保证完全复刻或自动通过质量验收。

移除参考只解除当前节点引用，历史原图不会立刻永久删除。节点或项目进入回收站时不能继续访问其参考图；恢复可重新访问；彻底删除时会清理对应本地原图。人物设定改变后需重新生成并采用当前版本，旧镜头成果仍保留供核对。

6. 画布生图与生视频

文稿确认后带入镜号、图片／视频提示词、来源与默认模型，每镜有图片和视频节点。默认图片为 Seedream V5 Pro，含人物镜头带入已采用定妆；默认镜头视频为 Seedance 2.5 图生视频，使用本镜当前成功图片作首帧。

  1. 核对人物和分镜，再进入创作画布。
  2. 图片卡片可点“参考图”补充构图、姿态、场景或风格参考，用法与人物参考窗口相同。已有采用的人物参考仍保留。
  3. 点击“画质／风格／提示词”调整本镜；勾选需要的图片并“生成所选”，查看本批费用后确认。
  4. 图片成功后检查，再生成对应视频。缺少当前有效首帧时不能开始图生视频。
  5. 不满意可修改提示词、参数或参考图，重新报价生成；旧结果保留在项目素材中。

视频节点本轮沿用现有首帧引用流程，参考图窗口用于人物和图片节点。添加、修改、移除参考会使旧报价失效；上传未完成时不能生成。不必每张图重新填写模型接口表单，但每批费用确认仍独立于文稿审核。

画布与布局

拖动空白处平移、卡片顶部改位置；缩放按钮或 Control／Command 配合滚轮缩放，“全览”查看全局。顶部导航定位镜头，图片在上、视频在下。可以新增自由图片／视频节点，收起右侧编辑器或讨论区，拖动分隔线调节支持的栏宽。专注模式铺满工作区，退出或 Escape 返回。

7. 参数与提示词

参数 操作与边界
图片比例 常用 9:16、16:9、1:1、3:4 等；按当前模型支持范围展示
清晰度 按模型提供 1K／2K 等选项，改变清晰度保留比例；像素在高级设置查看
视频参数 分辨率、时长、声音、草稿等按实际模型 schema 展示
内置风格 可选择风格或保持原稿；“查看画面与风格提示词”查看这两部分，参考用途说明由后台另行加入
批量参数 只对兼容同类节点应用；保留各自比例，不覆盖提示词与参考
更换模型 高级设置中选择；必须满足新接口的图片输入等必填条件
提示词优化 人物交 R05、镜头交 R06；应用建议才修改草稿

目标镜头时长与模型生成素材时长不同，工作台不会自动裁剪。改模型、参数、提示词、参考、选择或预算后重新报价；单纯平移与移动卡片不会主动使报价失效。降低清晰度是否更便宜，以新报价为准。

8. 模型连接

进入“工具与连接”，将自己的模型 API Key 保存并测试；日常无需重复配置。RunningHub 个人账号可能持有平台称作“企业级-共享”的模型 Key，名称不等于必须开通企业账户。

  • 模型 API：填“模型 API 密钥”，保存并测试，回项目选择模型和参数，取得官方报价。
  • 个人工作流：展开可选连接，填消费级个人 Key、工作流链接／ID和参考单价，测试并读取实际节点参数；提示词必须映射到正确节点。
  • 无限画布链接不是工作流 ID。“打开无限画布”仅跳转外部网页，外部任务不自动回填本地。

人物／图片参考窗口支持本地图片上传，但它不是所有模型、工作流、视频都通用的任意附件接口。其他输入仍按具体接口要求填写。已下架项禁用时不要强行重试；国际站 Image 2 尚未专门接入。

测试连接不会生成。报价和预算不是服务商实际扣费硬上限，任务未知时先查原任务编号与平台记录，再决定重试。密钥只填本机配置页，不发聊天或提交仓库。

9. 看大图、进度与成果

  • 点图片先看大图：弹窗内滚轮缩放，放大后拖动，使用“适应窗口”或“原始尺寸”；Escape／关闭返回。
  • 要下载时再点“下载原图”：远程地址的保存行为受浏览器与服务商响应影响，检查文件是否实际保存。
  • 画布显示排队、执行、成功、失败或未知状态，不编造过程百分比。
  • 项目“任务”看执行编号和错误；“素材”看已返回图片／视频；末尾“成果汇总”看主展示与各项结果。
  • 可“设为主展示”或将视频“设为最终成片”；这是展示选择，不代表自动剪辑、专业质检或发布已完成。

远程图无法加载可在弹窗重试；如果地址过期，应回项目检查该结果。能够播放不等于已经离线备份。

10. 伙伴与手动任务

团队伙伴工位可单独对话；项目内可 @姓名、@R03 或最多选择 4 人依次协作。独立工位不自动带入当前项目。便笺只记录内容，手动任务的责任人、复核人、依赖和拍板各自管理；模型输出文字不会自动代表用户认可。

11. 删除与备份

普通删除进入回收站；“恢复”找回，“彻底删除”“删除所选”“清空回收站”先显示不可逆范围。被引用、执行中、排队、未知或未同步内容需先解决阻塞。永久清理不删除 RunningHub 云端、外部导出或独立备份，也不会取消供应商任务。

本机运行目录含数据库、连接配置、原始参考图和运行附件，应一并私有备份；项目 JSON 不是完整备份。云端、本机 8767、便携 8768 相互独立，不会因切换入口而迁移。恢复前备份目标并停目标服务，勿直接覆盖运行中的库。远程结果要另行保存原文件，只有链接不能算完整素材归档。

现象 处理

夏夏工作台：技术架构与开发维护

盘点日期：2026-10-29。本文描述交接时磁盘上的代码，不代表所有外部模型均已实测。交付包逐文件数量和校验值以同目录 清单/全部文件清单.csv、清单/全部文件清单.json 为准。

1. 系统组成

以下描述本机单用户工作台架构；另有独立的云端 BYOK 版本（见本节末尾）。本机运行方式：原生 HTML/CSS/JavaScript 页面连接 Python 回环 HTTP 服务；SQLite 保存项目与执行记录；文字任务通过本机已登录的 Codex CLI 执行；图片与视频通过 RunningHub API 提交。Mac 客户端是同一网页的 AppKit + WKWebView 外壳。

flowchart LR
    U[总策划 / 浏览器或 Mac 客户端] --> UI[HTML / CSS / JavaScript]
    UI <--> S[Python 本机 HTTP 服务]
    UI <--> L[浏览器 localStorage 与会话草稿]
    S <--> DB[SQLite 项目快照与运行记录]
    P[21 角色原文与共享指令] --> R[RoleCatalog]
    R --> S
    S --> T[隔离的 Codex CLI 文字执行]
    S --> M[RunningHub 工作流 / 模型 API]
    M --> O[服务商托管的图像与视频 URL]
    O --> UI

这里的“团队”是角色化的软件协作，并非 21 个一直独立在线的真人或无限并行进程。角色能力说明、运行权限、实际工具连接与真实产出必须分开判断。

4. 数据流与真实能力边界

项目与草稿

lib/store.js 的浏览器状态包含项目、任务、决策、文稿、便笺和界面选择；workspace-sync.js 将内容快照写入 SQLite 的 workspace_snapshots。数据库通用 records 保存运行、自动协作、媒体、画布和回收站等记录。页面草稿与正式执行记录各自保留，不能把界面便笺当作已提交请求。

正常运行目录为 data/runtime/；便携交付入口使用 data/portable-runtime/。它们包含私有数据，不属于源码清单或公开素材。不要用静态服务器直接公开整个项目目录，也不要将这些目录上传代码仓库。

文字协作

固定流程为：R11 制作规划 → R03 剧本 → R05 美术设定 → R04 分镜 → R06 生成输入 → R11 交付整理。

  • stepwise：在剧本、美术设定、最终文稿交付三个节点等待用户审阅，并非每条内部消息都停一次。
  • continuous：连续完成上述文稿阶段，最终文稿交付仍等待用户确认。
  • 新建项目保存 reviewMode，自动协作继承；当前表单草稿优先，新一轮通常沿用上轮选择。
  • 文字执行器禁用 shell、浏览器、插件、图像生成和子 Agent 工具，只返回文字；不因角色描述而获得更多执行权限。
  • 游戏角色可进行工位对话和项目文本协作，当前固定自动流程不支持游戏项目。

人物资产先于实际分镜图和镜头视频制作。文稿、美术设定与来源版本准备好后，先核对角色、生成并确认定妆图，再利用这些资产制作镜头。R04 的分镜文稿阶段不等于已生成镜头图像。

图像与视频

media.py 接通 RunningHub 中国站工作流 API 和模型 API；canvas.py 将报价绑定到本次节点、输入参数、素材与预算。用户确认整批报价后按节点提交，不等于每张图都重复弹同一确认。参数或报价过期后需重新确认，未知结果不自动重试产生第二笔任务。

当前代码目录含 311 个模型操作：图像 99、视频 212；代码层可用标记为 305，禁用 6。公开目录原有 4 个下架项，加上代码记录的 2 个中国站实际下线操作。这个数字表示操作目录，不是 311 个不同品牌，也不是 305 个模型均已运行验证。

默认中国站生图使用 Seedream V5 Pro 文生图/图生图配对；每个模型的尺寸、比例、参考图和清晰度按其 schema 转换。个人账户可使用哪种 Key 取决于平台的接口要求；工作流 Key 与模型 API 共享 Key 分别保存。RunningHub 国际站 Image 2 的独立接入尚未完成，不能自动将中国站密钥转发到其他站点。

媒体返回通常仅存服务商 HTTPS URL，前端直接显示 <img> / <video>。当前没有通用本地媒体代理、视频下载缓存、自动剪辑合成或稳定封面抽帧服务；URL 保存成功不代表文件已离线归档或通过播放验收。

人物和图片节点的参考图

node.referenceImages 保存 {id, name, purpose, note}；用途为 general、appearance、clothing、composition、style。每图说明最多 1,000 字。原图位于运行目录的 reference-images/，文件 0600、目录 0700，不属于公开素材或 Git 仓库。

  • POST /api/projects/{projectId}/reference-images：JSON 含 nodeId、name、contentBase64，沿用同源 CSRF；PNG／JPG／WebP，每图 10 MB，每节点最多 10 张。
  • GET /api/projects/{projectId}/reference-images/{id}：验证项目／节点归属及可见状态，返回 inline 图片，不暴露整个运行目录。
  • 前端只配对可用的同系列图生图，保留合法共有参数。占位 URL 仅用于校验，不持久化或实际提交。
  • CanvasManager 组装输入时按“已采用人物图 → 用户参考图”排序；同时验证模型 imageUrls.maxItems，用途与说明由后端追加一次。
  • 本机选图不调用供应商。报价准备上传到 RunningHub /openapi/v2/media/upload/binary，使用返回的临时 download_url；按 23 小时缓存，并处理临近到期时重新准备。

  • 参考 ID、顺序、用途和说明进入执行哈希。变更使旧报价失效，上传未完成不能生成。
  • 移除引用不直接删除历史原图；回收站隐藏后不再提供预览，恢复可见；永久删除节点／项目纳入既有暂存和回滚清理机制。

视频节点沿用已成功镜头图作首帧，不将参考窗口扩展成任意视频输入上传器。接口模拟与本机交互已验证，付费参考图生成及质量验收尚未完成；详见 docs/plans/2026-10-26-reference-images.md。
