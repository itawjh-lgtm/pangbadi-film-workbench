## 二、首次在另一台 Mac 启动

1. 安装 Python 3；本次在 Python 3.14 上验证。页面和后端不要求 npm install，也没有第三方 Python 服务依赖。
2. 从私有 GitHub 仓库克隆，或打开桌面交付中的 `01_源码与资源/`。
3. 双击 `scripts/start-portable.command`，或者在源码根目录执行 `bash scripts/start-portable.command`。
4. 浏览器打开 `http://127.0.0.1:8768/`。首次是独立数据环境，页面中的示例不代表原项目数据已恢复。
5. 需要文字生成时，安装并登录 Codex CLI。可在启动前设置 `STUDIO_CODEX_BINARY` 为实际可执行路径；先执行 `codex --version`、`codex login status` 检查环境。
6. 需要图像/视频时，进入工作台连接配置，填写 RunningHub 连接信息并测试。Key 不用写进代码或提示词。
7. 使用教程见 `03_用户操作手册.md`，先创建一个测试项目，再按 SOP 验证文稿→人物资产→画布。

终端保持开启；Ctrl+C 停止此便携实例。另需端口时使用 `STUDIO_PORT=8769 bash scripts/start-portable.command`。改变端口会改变浏览器存储来源，旧端口的未同步缓存不会跟随迁移。

便携模式固定读包内 `prompts/`，默认写 `data/portable-runtime/`。原 `启动工作台.command` 和 Mac 客户端仍读原岗位库、使用 `data/runtime/` 与端口 8767。

手动运行等价方式：

```sh
python3 -m server.httpd --port 8768 \
  --data-dir data/portable-runtime \
  --film-dir prompts/影视Agent团队提示词 \
  --game-dir prompts/游戏Agent团队提示词
```

## 三、这次备份覆盖什么

| 内容 | 保存位置 | 恢复后能获得什么 |
|---|---|---|
| 应用源码、界面资源、角色原文 | 源码目录 / GitHub | 当前代码与设计、提示词能力描述 |
| `studio.sqlite3` | 私有备份 runtime | 项目、任务、协作运行、文稿索引、媒体任务、回收站等持久化记录 |
| `runs/`、历史 runtime 备份 | 私有备份 runtime | 已保存的模型输入、角色快照、文稿文件 |
| `connections.json` | 私有备份 runtime | 本机连接配置和密钥；保留 0600 权限 |
| 历史 QA / 截图 / 实测记录 | 私有备份 historical-qa | 过去的验证证据，不能当作本轮最新验收 |
| `dist/` 本机产物 | 私有备份 local-build | 历史 Mac 外壳；内部仍指向原路径，不能直接当便携安装包 |
| 浏览器未同步数据与页面偏好 | 本次未自动导出 | 需要在原窗口使用“导出工作台 JSON”；不同浏览器缓存独立 |
| 供应商远程图片和视频 | 主要保存 URL 在数据库中 | 不保证远程链接长期有效，也不等于媒体已经离线下载 |

本次对 SQLite 使用 SQLite backup API，备份库执行 `PRAGMA integrity_check`。没有把运行中的主库文件和 WAL 随意拼接。运行文件目录按复制时间保存；若复制期间有正在写入的任务，数据库时间点和后写入文件可能不同。严格停机快照应先等待当前任务完成、停止后台，再重复备份。

私有目录权限为 0700，普通文件为 0600，原可执行文件保留为 0700；其中含用户项目资料和密钥。它与 Git 仓库同级，不在仓库内。桌面是否由 iCloud 同步由用户的系统设置决定，这个本地备份本身不是加密保险库。

## 四、恢复数据（先恢复到隔离实例）

1. 退出目标便携实例，关闭其网页标签；确保没有后台继续使用 `data/portable-runtime/`。
2. 如果目标数据目录已存在，将整个目录重命名留存，不要直接覆盖其中部分文件。
3. 恢复原正式数据时，把私有备份的 `runtime/` **整个复制**为源码目录中的 `data/portable-runtime/`。保持目录与文件限制权限。若要恢复后来产生的便携项目，则选择备份中的 `portable-runtime/`；不要把两份库混合。
4. 确认 `studio.sqlite3` 存在；若旧目标残留 `.sqlite3-wal`、`.sqlite3-shm` 或服务锁，说明没有正确使用全新目录，应返回上一步重新操作，不把它们混进快照。
5. 用便携启动入口运行，检查项目数、名称、文稿版本、人物资产、媒体结果和回收站是否符合预期。
6. 如果同一浏览器曾打开这个端口，使用新的浏览器配置或明确处理工作台同步冲突；不要让旧缓存覆盖恢复数据。
7. 核对未结束任务的恢复状态。提交结果不明的供应商任务先核对平台记录，不要重复点击生成导致重复扣费。
8. 远程结果分别打开核查；缺失的视频需要从仍有效的供应商入口另行保存。

本次不执行上述恢复，不改变原项目数据。数据库可恢复不代表 Codex 账户登录、供应商余额或外部授权已经恢复。

## 五、Mac 客户端与部署边界

现有客户端源码在 `desktop/`，采用 Swift/AppKit + WKWebView，Bundle ID 为 `cn.dreamstudio.workbench`。网页已经改为庞巴迪影视工作台，原生应用仍叫造梦工作室。

在有 Apple Command Line Tools 的 Apple Silicon Mac 上，可按 `desktop/README-native.md` 运行构建。构建配置包含本机项目路径和 Python 路径；本次没有重新构建、更名、安装、签名或公证。`dist/` 只在私有本地备份中保留，GitHub 提供可重建源码。

服务只绑定回环地址，具备同源和写操作 token 校验。不要通过简单改为 `0.0.0.0` 或端口转发当作公网产品。公网服务仍需独立设计身份认证、权限、资源限额、存储、供应商密钥管理与部署安全。

## 六、后续更新 GitHub

当前 Git 仓库在交付目录的 `01_源码与资源/`。若继续在原项目目录开发，先将明确修改同步到这个交付仓库，排除所有运行数据，再审查差异和提交。不要在上级“AI 影视”目录运行全量 add。

```sh
git status --short
git diff
# 仅添加本次明确的代码、资源和文档文件
git add <明确的相对路径>
git diff --cached --stat
git commit -m "Describe the reviewed change"
git push
```

请保留私有属性。`.gitignore` 不能删除已经进入历史的秘密；一旦误提交密钥，须撤销密钥并清理历史，不能只补一条忽略规则。
