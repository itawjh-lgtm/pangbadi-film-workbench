## 二、历史验证如何理解

原 `docs/qa/` 中保留了不同阶段的测试报告、真实调用记录和截图，随桌面备份位于 `02_本地私有数据备份/historical-qa/`，不上传 GitHub。这些记录含私人项目和账户信息，应按各自记录日期、版本和范围阅读。

历史上曾有真实图片返回、视频结果打开播放、自动协作文字和人物/画布链路检查；这些事实不能推出所有项目已经完成、所有视频都合格或全部接口今天仍有效。旧文档中的模型目录数量、禁用数量及费用也不是当前承诺。

## 四、此次交付验收方法

1. 打开桌面 `00_从这里开始.html`，能进入完整阅读页并看到 21 位伙伴资源。
2. 查阅七份中文手册；SOP 覆盖输入、责任岗位、动作、交付、审核和返修。
3. 在代码目录运行 `python3 scripts/package-handover.py --verify .`，应返回 passed。
4. 查看 GitHub 仓库为 **公开仓库**，包含代码、提示词和资源，不含运行数据库、连接密钥、个人项目/账户 QA。
5. GitHub HEAD 与桌面源码目录的提交一致。
6. 私有备份数据库 integrity_check 为 ok；根据 `06_部署备份与恢复.md` 才能恢复，不能直接覆盖运行中的库。
7. 打开云端实际地址，登录并检查账户隔离、配置状态和新建项目；把此项人工验收结果另行记录，不使用模拟测试替代。
8. 在已安装 Mac 0.6 中切换本机／云端入口，确认显示对应的数据；切换不应迁移原本机数据库或 Key。
