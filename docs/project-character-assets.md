# 项目人物资产与分镜依赖

独立“人物资产”列表中的项目人物来自当前项目已确认的 R05 美术原稿。工作台的员工形象不作为项目角色参考。R05 文字通过确认只会建立人物草稿，不能视为已生成或已确认的人物图片。

页面使用顺序为：文稿／美术设定 → 人物资产独立列表 → 分镜 → 创作画布。媒体依赖顺序为：人物定妆图片 → 用户确认人物图片 → 分镜图片复用这些参考 → 同镜分镜图片作为视频首帧。无人物的纯场景镜头直接使用文生图，不强制绑定全体角色。

分步审阅中，R05 美术稿完成并由用户批准当前输出版本后，即可进入人物资产；不必等待 R04、R06 或最终交付完成。连续执行模式没有 R05 独立用户审批时，仍待最终用户总审。R05 批准后后台文字分镜仍可继续运行；这里的页面顺序和媒体依赖不表示已有“人物图确认后才启动 R04 文字分镜”的调度硬闸。

## R05 人物资产说明

新执行的 R05「角色与视觉设定」必须交付人物总表和逐人明细，不能只交风格方向。总表使用稳定且唯一的 `CHR-001` 等编号，列出人物名、身份与年龄、依据与性质、出场关联。每人独立一张卡；只有确有群像需求时才单列群像并写明成员差异。

人物卡的 12 个说明字段是：身份与年龄、外貌与身形五官、发型、服装与配饰、辨识特征、性格与表演、定妆视图、参考图生成提示词、不可改变项、换装版本、出场镜头关联、依据与性质。原作未知的年龄、外貌和性格不得编成事实，创作建议应明确性质。R05 早于 R04，尚无镜号时关联已有剧本场次，并注明镜号待 R04 编排。

可解析的最小完整格式示例：

```markdown
## 人物资产总表
| 资产编号 | 角色名 | 身份与年龄 | 依据与性质 | 出场关联 |
|---|---|---|---|---|
| CHR-001 | 林遥 | 实习修复师，约22岁观感 | 原创设计 | S01修复室 |

## 人物资产明细
### CHR-001｜林遥
- 资产类型：人物
- 身份与年龄：实习修复师，约22岁观感，年龄为创作建议。
- 外貌与身形五官：清瘦、中等身高、长椭圆脸、平直眉、浅棕肤色。
- 发型：黑色齐肩直发，左侧分缝，右侧收耳后。
- 服装与配饰：雾蓝工作衬衣、米白长裤、白鞋、左胸布袋。
- 辨识特征：左眉尾浅疤、圆形铜扣、左右不对称发型。
- 性格与表演：谨慎专注，观察时微前倾，笑容克制。
- 定妆视图：正侧背全身及头像特写，未生成、待审。
- 参考图生成提示词：
> 单角色无字定妆设定图，3:4，正侧背全身及头像保持同一脸型，黑色齐肩直发，左分缝，左眉尾浅疤，雾蓝工作衬衣、米白长裤、白鞋和圆形铜扣，二维漫画，低饱和色彩，中性背景。
- 不可改变项：左眉尾浅疤、分缝方向、铜扣及基础服装。
- 换装版本：当前仅基础版，无换装要求。
- 出场镜头关联：关联剧本S01修复室；镜号待 R04 编排。
- 依据与性质：示例角色为原创设计，非已核实原作信息。
```

场景和道具单独用 `SCN-`、`PROP-` 编号。制作团队、工作人员、R01—R16 岗位不进入人物清单；但明确为剧情人物的“工作人员甲”等可作为项目人物。纯场景项目明确写 `人物资产：无；本项目无需人物资产` 并说明依据，系统不会为凑齐人物表虚构角色。

自动协作的读取响应在 `visual.characterAssetReport` 附加只读文本完整性报告，包括：

- `contractVersion: 1`、`characters`、`warnings`、`noCharactersDeclared`。
- 每个人物包含 `sourceAssetId`、`name`、`description`、`sourceArtifactId`、`sourceRange`、`aliases`、`sourceNature`、`fields` 和中文 `missingFields`。
- `fields` 的机器键为 `identityAge`、`appearance`、`hair`、`costume`、`distinctiveFeatures`、`performance`、`views`、`referencePrompt`、`immutableTraits`、`variants`、`shotLinks`、`sourceBasis`，仅保存原稿中明确存在的字段文字，不补猜缺失值。
- `status`：`ready` 只表示字段齐全；`needs_details` 表示缺项或解析冲突；`not_applicable` 表示明确无需人物；`not_started` 表示尚无可读原稿。
- `evidenceLevel: "text_only"`、`imageApprovalIncluded: false`。文字完整性不代表事实核实、美术质量通过、图片生成或用户验收。

读取已有完成阶段时会派生报告，但不会改写原稿、审阅记录、计划版本或重新执行 Agent。历史的编号章节格式仍可提取已有角色，也支持本人物卡内的两列 Markdown 说明表：“年龄观感”对应身份与年龄，“固定辨识点”对应辨识特征；眉眼、鼻口、面部轮廓等明确外貌行可聚合，保留“待原作核实”等限定原文。其他人物或场景章节的表格不能借来补齐此人物。

没有识别到独立标签时，相关内容仍保留在说明原文中，提示为“未识别独立字段，请核对/补充”，不声称原稿完全没有该信息。字段 lint 不阻止用户确认历史稿。重复 CHR 明细或多份当前原稿使用同一编号时提示冲突，不任意选一份导入，也不删除已有的人物和图片。

需要补齐时，由用户显式调用原有 `review(action="revise", stageId="visual")` 返修入口。返修会保留旧版历史、执行新 R05 版本，并使后续文稿重新审阅；不能把“查看缺项”或“打开人物清单”当作同意重跑。

## 读取与编辑

`GET /api/projects/:projectId/canvas` 返回 `characterAssets`。每个资产含人物名称、可编辑提示词、`nodeId`、来源文稿与行范围、来源版本、来源资产编号、参考图任务/输出索引、当前确认信息及历史。自动资产 ID 对项目、来源资产编号及 R05 来源版本确定性生成。

资产状态：

- `draft`：没有可确认的成功人物图片。
- `pending_review`：已有成功输出，尚未由用户确认；确认 API 仍校验输出格式和输入版本。
- `ready`：用户已确认，当前提示词及参数未变化，输出仍属于本项目本人物节点。
- `stale`：来源版本、提示词或参数发生变化，需要重新生成/确认。
- `missing`：依赖已删除或图片链接明确过期，需恢复依赖或重新取得图片。

人物列表与创作画布共享项目资产记录，人物提示词和模型参数沿用画布的保存 API；两页各自展示相关节点，隐藏节点不会因页面保存而被删除。移动、选择节点不使人物确认失效；修改提示词或生成参数会使旧确认失效。历史图片和确认记录仍然保留。

返修或同提示词重生返回新的有效图片时，资产重新进入 `pending_review`。响应的 `reviewCandidate: {jobId, outputIndex, url}` 是当前输入版本的可采用候选，页面以它展示预览和提交整组采用；不自行猜测最近任务。原 `reference*` 和确认历史保持原值，`referenceUsable` 说明旧参考是否仍满足当前输入。采用时记录当时已返回的候选任务集合；其他旧结果不会重新变成待采用，仍在运行的任务之后返回时仍会出现新候选。采用某张图片不表示其他输出被质量验收。

## 新增与确认

- `POST /api/projects/:projectId/canvas/assets`：传入 `name`、`description?`、`prompt`、`expectedRevision`，返回 `201 {canvas}`。用于手动创建项目人物。
- `POST /api/projects/:projectId/canvas/assets/:assetId/confirm`：传入 `jobId`、`outputIndex`、`expectedRevision`，返回 `{canvas}`。只确认现有成功图片，不发出生成请求。
- `POST /api/projects/:projectId/canvas/assets/confirm-batch`：传入 `items: [{assetId, jobId, outputIndex}]` 和 `expectedRevision`，返回 `{canvas}`。全部项目先校验，再以一次画布写入完成整组采用；任一失败时没有部分确认。重复采用同一任务、输出和输入版本保持幂等，不增加资产版本。

确认要求图片任务属于同一项目、同一人物节点，且 `canvasNodeHash` 等于当前输入版本。只接受有效 HTTPS PNG/JPEG 输出；可识别的过期时间及 AWS 签名有效期会被检查，不声称已联网验证远端可访问性。视频输出不能确认为人物定妆。

## 镜头生成

自动图片节点带 `characterAssetIds`，来源是 R06 逐镜角色引用/所需参考图。没有显式引用时才使用当前镜头正文匹配人物，不将全员默认应用于所有镜头。

前端可以用 `ready` 资产的 `referenceUrl` 填充模型表单；后端重新读取已确认资产并构建 `imageUrls`。清空客户端人物列表、伪造 URL、修改自动节点来源都不能绕过原稿中的依赖。已删除人物、原稿、媒体及项目会阻止继续使用；恢复仅恢复资料，不产生新的收费任务。

自动视频节点默认 `SHOT_VIDEO_MODEL`（Seedance 2.5 图生视频），首帧必须是同镜当前版本的成功图片。视频参数中的 `firstFrameUrl` 由后端重建。失败任务、旧输入版本图片、其他镜头图片不能用作该镜头的当前首帧。

含人物的分镜任务另外保存 `characterReferenceSnapshot`，记录资产编号、资产版本、来源版本、确认任务、输出索引、图片地址和确认输入哈希。视频生成前重新校验人物仍为可用状态，且成功分镜图片任务的实际 `parameters.imageUrls`、人物版本快照与当前确认全部一致。缺少任一输入/版本证据的旧图不能作为当前首帧；即使图片地址相同，人物换了生成任务或版本也须重新生成分镜。无人物纯场景的历史首帧不要求人物快照。视频节点保留人物关联，但不向视频模型传入人物 `imageUrls`。

图像模型取媒体模块的成对默认常量 `DEFAULT_CN_IMAGE_MODEL` 与 `DEFAULT_CN_IMAGE_EDIT_MODEL`，当前为 Seedream 5 Pro 文生图/图生图。采用显式 width/height，人物为 1536×2048，9:16 镜头为 1152×2048；不传会覆盖尺寸的 resolution。镜头采用原稿明确画幅；未明确时保留方形默认值。中国站已对 G2 及旧 Ultra 官方文生图返回下架错误，两个已知下架接口已禁用；不能据此声称同系列图生图接口也已下架。新默认尚不代表真实生成或质量验收。

画质常用控件位于编辑面板顶部：图片常用区为 9:16、16:9、1:1、3:4 等比例和 1K／2K 清晰度，自定义宽高留在高级设置；视频参数按当前模型能力提供分辨率、时长、声音与草稿，并区分原生分辨率与超分档位。风格保留“原稿”选项并提供 31 种实际风格。画质和风格可分别应用到勾选的同类项；批量画质只覆盖同模型节点并保留目标比例，不改提示词与引用。参数或风格变化会使旧报价失效，需重新估价，实际成本以平台账单为准。

所有生成仍经过既有整批估价、确认与幂等提交。同步、读取、新增人物和确认图片本身不调用付费生成。

## 版本与布局

人物在独立列表管理，创作画布只展示相应镜头，按横向排列、图片在上、视频在下。共享存储仍保留人物节点及旧位置，页面分离不删除原数据。首次升级保留旧位置快照和迁移前节点快照；已有媒体、提示词及结果记录保留。R05 新版本建立新人物草稿，旧人物标为过时而非覆盖。新增版本镜头放在空闲尾部，避免与既有节点重叠。

存在待做项目人物时，初始只选择人物定妆节点，镜头不会一并进入“生成所选”。确认的人物取消选择，避免误重复生成。

仅新建自动人物草稿采用加强后的美术指令：保留 R05 身份、年龄观感与服装特征，明确五官/发型辨识度、协调比例、服装剪裁层次、低饱和配色、线条和材质；单角色绘制无字正侧背全身及头像定妆图，群像依据来源区分各人脸型。它是待执行的生成要求，不是已生成或已审图结论；已有用户编辑不被覆盖。

离线回归使用临时数据库与模拟媒体服务，覆盖来源提取、版本确认、同镜首帧、依赖删除／恢复、客户端绕过、批次幂等和历史迁移。本轮画质与风格交互仅做隔离模拟报价及 UI 测试，没有新发起真实付费生成，不能据此认定新默认的实际画质或扣费已验证。

默认图片模型迁移独立使用 `modelMigrationVersion`，不触发布局和制作流程重建。仅旧自动默认、尚未生成或仅有明确失败记录的节点迁移；成功、在途、未知状态、记录缺失、用户显式自选模型均保留。旧参数/节点完整存入 `migrationHistory`，画幅换算为新模型支持的尺寸，提示词、位置、选择、引用、结果与历史不改写。`modelSelectionOrigin` 记录自动默认或用户自选，不计入生成输入哈希；服务启动先用已保存的明确下架错误回填本机模型可用性，不联网、不重发生成。
