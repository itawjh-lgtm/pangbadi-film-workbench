# Bot 风格团队工作台 Implementation Plan

**Goal:** 将现有21人展示与固定协作演示升级为项目、独立工位、任务、决策、成果相互关联的本地协作原型。

**Architecture:** 无构建的模块化单页：employees + project-templates 为只读目录，store 负责实体/校验/状态迁移，views 负责展示，app 处理交互与生命周期。原有路径保留，旧界面先备份，头像资产不改。

**Tech Stack:** 原生 HTML/CSS/JavaScript；localStorage 本地保存；对话预览通过 host widgetState 保存有限快照。未接入模型、后台执行器或第三方工具。

## 参考与设计取舍

- 官方参考：https://x.ai/bot 、https://docs.x.ai/grok-bot/bots 、https://docs.x.ai/grok-bot/chat-and-collaboration 、https://docs.x.ai/grok-bot/files-and-results 。2026-10-23读取。
- 借鉴固定职责的员工、项目群会话、单独会话、可追溯交接、可预览成果；本项目采用已有可爱3D人物、黑白与荧光绿品牌。并非像素级复制或接入Grok。
- 默认采用项目协作台，保留团队大厅。纯聊天界面会隐藏依赖；继续只做人物卡则无法组织实际项目。
- 当前数据均为示例或用户手动登记，任何本地发送/交接都不可写成已发送给Agent或已执行。

## 文件与实施

1. `data/project-templates.js` + `lib/store.js`：v3实体、任务依赖与决策门禁、上游返修、状态校验、v2收藏迁移、有限host快照。
2. `index.html` + `styles.css`：侧栏、工作区、任务检查区；移动端重排；沿用21张人物图与原有强调色。
3. `lib/views.js` + `app.js`：总览、项目群/单独会话、任务看板、团队搜索收藏、共享成果、连接状态；新建项目/任务、手动更新、拍板/返修、成果登记和JSON备份。
4. `scripts/build-preview.py`：按顺序内嵌所有模块与21张缩略图，保留独立根与宿主状态协议。
5. `tests/store.test.cjs`：覆盖迁移、恢复、错误输入、依赖/决策、返修下游失效、保存与消息边界。
6. 验证页面可用操作、移动端布局及21张图哈希；保存QA记录，更新README与架构说明。

## ADR-001：模块化单页而非21套应用

共享项目和资产状态，角色分别保留工位与对话。代价是本地存储不具备真正用户隔离与多人同步。后续执行器通过统一任务/结果事件接入，不拆成21份基础设施。

## ADR-002：状态变化不等同实际执行

会话只保存本地便笺；示例回复显式标记。任务由用户手动登记，完成需结果依据与复核备注；界面不伪造自动进度、费用、授权或发布。

## ADR-003：兼容旧状态和保存失败

保留旧storage key作迁移来源；旧演示步数不变成真实任务结果。限制数据量、转义用户文本、拒绝循环依赖。localStorage失败有可见提示，host只存符合大小约束的快照，不用截断状态覆盖完整本地数据。

## 非功能要求与验收

- 离线可打开，无构建与新增外部依赖；无秘钥、未授权上传或发布。
- 320–1440布局可重排，控件键盘可操作；对话预览不依赖原图文件路径。
- 核心链：创建项目 → 分配任务 → 上游完成 → 总策划决策 → 下游推进 → 返修失效 → 刷新回读。
- 保存失败、损坏状态、旧状态迁移、空项目和无搜索结果都提供可见状态。
- 头像原图哈希与升级前一致；新界面仍能查看全部21个角色。
