# Project Creation Canvas Implementation Plan

**Goal:** 按文稿／美术设定 → 独立人物资产列表 → 分镜 → 创作画布推进；已确认的逐镜提示词自动落入可编辑画布，模型与参数提供默认方案，以一次批次费用确认完成所选多图／多视频任务提交。

**Architecture:** 保留现有项目、自动协作与分镜真源。画布持久化节点布局和用户草稿，后台批次队列调用既有 RunningHub 适配器。媒体结果仍属于原项目、镜头和来源版本；不把画布导入等同于生成。

**Tech Stack:** 原生JavaScript/CSS、Python HTTP服务、现有SQLite记录存储、RunningHub模型API、本机Codex R05/R06文字执行器。

## Task 1: Canvas state and automatic import

- 新建 `server/canvas.py`，修改 `server/httpd.py`。
- R05 美术设定在分步审阅中经用户 approve 后即可独立提取人物资产，不依赖 R04 或最终交付完成；核对真实审批人和当前 artifact 版本，不将阶段自动完成当作用户批准。
- 连续模式没有单独 R05 用户批准时，仍须等待最终交付用户总审。R05 批准后，后台 R04 文字分镜仍可继续；当前没有等待人物图片采用的文字调度硬闸。
- 最新 production 最终交付经用户 approve 后，按 production 和分镜／提示词 artifact 版本幂等导入图片／视频节点。
- 保留完整镜号（如 `S01-001`、`S01-002`），逐镜匹配图片与视频提示词，不把同场景内多个镜头折叠成一个节点。
- 新审批版本先准备对应人物资产或画布入口，再引导进入后续制作；首次读取历史完成记录不抢导航，同步期间用户切页、新输入或打开弹窗时保留当前操作，继续入口可手动重试。
- 保存节点位置、选择、参数、提示词草稿及视口，revision冲突不能覆盖另一窗口修改。
- 新版文稿新增来源版本，保留已有编辑和历史产物。
- `tests/test_canvas.py` 覆盖审批门槛、重复导入、版本、项目隔离、保存冲突。

## Task 2: One batch quote and execution

- 批次包含明确所选节点、各模型/参数、项目来源、预计金额与币种；参考预算可选，留空时仍可根据本批报价确认。
- 估价不生成；用户一次确认批次后持久化队列，逐项提交并自动查询服务商状态。
- 保留报价过期/参数绑定/凭据版本/幂等保护；未知提交不得自动重试。
- 预算用于提交前核对预计费用，不承诺成为服务商扣费硬上限；实际费用以 RunningHub 账单为准。
- 浏览镜头、平移缩放和调整布局只保存视图，不使报价失效；更改所选节点、提示词、风格、模型、参数或预算后重新报价。报价自然过期仍需重新获取。
- 停止操作只阻止尚未提交的项目，已在服务商运行的任务继续查回状态。
- 服务重启恢复已知任务查询，不重新提交结果未知的条目。
- 离线测试模拟中断、重复点击、预算变化、失败、停止和恢复。

## Task 3: Project infinite canvas

- 新建 `lib/canvas.js`、`styles/canvas.css`；集成 `app.js`、`lib/views.js`、`lib/runtime.js`、`lib/store.js`、`lib/production-views.js`、`index.html`。
- 项目新增“创作画布”，大点阵画布支持拖动节点、平移、缩放和适配全部。
- 默认专注模式、顶部逐镜导航、每镜图片/视频成对呈现；直接点击节点生成按钮或底部“生成所选”，展示预计费用后一次确认。
- `lib/canvas-controls.js` 提供常用控制：画质常驻编辑面板顶部，原稿风格之外有 31 种实际风格。模型目录与其他参数收进“高级设置”，不要求每镜重新选择模型。
- 图像可选保比例的 1K／2K 预设及自定义宽高；视频根据真实模型字段提供分辨率、时长、声音与草稿控件，明确原生分辨率和超分档位，不显示为所有模型通用能力。
- 画质与风格分别批量应用到勾选同类项。批量画质限同模型并保留每个目标比例，不修改提示词或引用；修改后旧报价失效，重新估价后再确认提交。
- 默认图片为 Seedream 5 Pro 文生图／图生图；定妆及纯场景文生图，有人物的分镜引用已确认定妆进行图生图。人物默认 1536×2048，9:16 镜头默认 1152×2048；显式宽高时不传 `resolution`，避免服务商覆盖比例。视频为 Seedance 2.5 图生视频，必须引用同镜当前人物版本的成功图片；明确画幅从分镜与提示词继承，视频时长按模型支持值预设。
- 分别显示目标分镜时长与生成素材时长。模型最短时长长于目标时，生成的素材留待剪辑取用；超出最长支持时长的镜头需要拆分或另行制作，不声称已自动完成剪辑。
- 节点显示真实进展、图片/视频及失败原因；原分镜生成入口定位对应节点。
- 人物定妆在独立“人物资产”列表展示，位于分镜前；创作画布展示镜头，镜头从左向右、图片上方视频下方。首次人物生成只选择待做定妆，不夹带镜头；角色定妆可整组原子确认，修改造型或确认版本后相关下游重新检查。两页共享项目与版本记录，隐藏节点不会因页面保存而删除。载入页面本身不触发收费调用。
- 画布内置团队对话与真实媒体状态；任务页展示执行队列，素材页仅展示成功产物。

## Task 4: Prompt optimization

- 使用现有 `runtime.start`：人物定妆由 R05 产出美术建议，普通镜头由 R06 优化。加载完整岗位说明，保留原稿身份/年龄/服装，不声称已生成或已视觉审查。
- 保存runId/requestId/来源与原稿快照，结果只作为候选，用户应用后才替换画布草稿。
- 长文本、同项目执行冲突、请求结果未知和旧优化结果均明确处理。

## Task 5: Submission diagnostics and verification

- G2 及旧 Ultra 官方文生图均已有中国站明确下架证据，禁用对应接口并保留官方错误码／原因；不据此推断同系列图生图全部下架，不跨站或重复付费提交猜问题。
- 旧自动默认的安全迁移使用独立 `modelMigrationVersion`，保留节点快照和用户编辑，不触发布局重建；成功、在途、未知状态、缺失记录及用户自选模型不自动改写。启动时仅用本机明确失败记录回填下架证据。
- 修正提示词画幅与参数冲突；批次预览核对最终参数。
- 完成相关Python/JS回归，安全重启空闲本机服务，在真实项目检查导入、编辑、保存与批次报价。
- 补充完整镜号、逐镜提示词配对、自动转场去重、同步期间导航/输入保护、默认方案、可选预算与纯浏览保留报价的回归；使用隔离模拟服务验证交互，不把模拟媒体结果当成服务商真实产出。
- 本轮仅使用隔离模拟报价与 UI 测试，没有新发起真实付费媒体生成；新默认真实出图、视频播放、画质和扣费结果另行验收。
